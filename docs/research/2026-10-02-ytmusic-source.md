# 認証ありYTMusicの取得元・照合実験

## 方針

推薦の主な取得元はYTMusicの曲ラジオと関連曲とする。MusicBrainzは
必要になった場合の録音・メタデータ識別補助で、今回の取得には使っていない。
ジャンルは当面優先しない。Appleのgenre IDとの対応は未解明で、
ジャンルフィルターを外す実験設定の実アプリ・iPodでの受け入れも未確認。

取得結果の順序はAppleのGenius rankとは別に保存する。
曲名・アーティスト・長さによる一致は候補で、同じ録音という確定ではない。
ライブ、リミックス、伴奏などの版表記を削除して同一視しない。

## 保存済み結果の再集計

「ツバサグラビティ」の2回分について、取得時の照合候補を数えた。
1回目は旧照合方法、2回目は長さを考慮する方法のため、照合数の差を
推薦の変動だけに帰属させることはできない。

| 項目 | 1回目 | 2回目 |
| --- | ---: | ---: |
| 観測行 | 70 | 70 |
| radio行 | 50 | 50 |
| related行 | 20 | 20 |
| ユニークvideo ID | 65 | 66 |
| 種曲以外でローカル候補があるvideo ID | 11 | 7 |

両回に共通するvideo IDは56、和集合は75。
この結果ではアカウント認証成功を証明できていない。

## 10曲の実験準備

`scripts/probe_ytmusic_batch.py`を追加した。

- ローカルライブラリからアーティスト表記とアルバム表記が重ならない10曲を選ぶ。
  曲数の多いアーティストを優先するため、無作為標本ではない。
  Off Vocal / instrumental / カラオケの明示表記は種曲から除外する。
- アカウント情報APIでアカウント項目が確認できたときだけ検索・推薦取得へ進む。
  アカウント名・画像・ハンドルは保存しない。
- HTTP request呼び出しの開始間隔は既定5秒、1回の実行で最大45呼び出し。
  タイムアウトは25秒。エラーはその実行を停止し、自動再試行しない。
  これはサービスの許容上限を確認した値ではなく、この実験の自己制限。
- 検索はsongsを指定し、曲名・アーティスト・長さでvideo ID候補が1つに
  絞れた場合だけ収集する。それでも録音の同一性はunverifiedのまま。
- 成功したAPI応答は許可した曲情報のフィールドだけキャッシュする。
  同じ実験ディレクトリでの再実行では成功済みの問い合わせを再送しない。
  キャッシュの取得日時を保持し、推薦を再観測したいときは別ディレクトリを使う。
- `--plan-only`ならネットワークを使わず種曲一覧だけ作成できる。

種曲一覧はignoredな `data/ytmusic/coverage-01/seeds.json`に保存した。
元LibraryとGenius DBへの書き込みはない。

## 実行結果と残る条件

最初の実行はネットワーク制限でConnectionErrorとなった。
制限外での実行ではget_account_infoがKeyErrorとなり、検索前に停止した。
個人情報を出さない診断でaccount/account_menuのHTTP 200応答を確認したが、
accountNameとactiveAccountHeaderRendererは存在しなかった。
multiPageMenuRenderer等は存在した。

このため現在のbrowser.jsonでログイン状態を確認できない。
期限切れと応答形式変更のどちらかはこの証拠だけでは断定しない。
新規の曲検索・推薦データは取得していない。認証情報を更新して再確認することが
次の条件で、引き続き欠落する場合はaccount APIの形式を調べる。

19テストのうち15件が成功、提供Musicバイナリが必要な4件は通常設定でスキップ。
追加テストは、認証応答欠落時の停止、秘密フィールドを保存しないキャッシュ再利用、
種曲のアーティスト・アルバム分散を検証した。
